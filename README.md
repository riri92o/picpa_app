# PicPa

1日1色を引き、その色に合わせて4・6・9枚の写真でコラージュを作る、モバイル向けのローカルWebアプリです。写真、完成記録、設定はIndexedDBに保存します。サーバーやアカウントは使いません。

## Homeの抽選前・抽選後（2026-10-19）

抽選前は中央の「？」バブル、周囲の色の泡、「タップして今日の色を引く」を表示します。写真欄・枚数・間隔・完成ボタンは、色が決まってから表示します。通常モードの枚数選択も抽選後に行います。ランダムチャレンジの抽選・ロック規則は維持します。

既存の集合・渦・ばねで追従する尾・収束を使い、色の決定後は中央で650ms見せてから850msで上部の色表示へ移動します。その後、写真欄と枚数・間隔・進行枚数をまとめた操作欄を表示します。再訪時に抽選済みなら最初から上部に表示し、動きを減らす設定では混色と移動を省略します。日付変更・非表示時のキャンセルも維持します。

`SoapBubbleSurface` がHomeの透明な膜・縁の虹色・反射を描きます。`ui/soapFilm.ts` は球面の反射方向と縁の透過率から、左上の柔らかな光源と薄膜の色を計算します。硬い白い楕円や太い反射帯を重ねず、色と状態ごとの材質を384pxで一度だけ描画して、最大16件のメモリキャッシュで再利用します。背景・ナビ・完成時の泡も同じ材質を使い、浮遊や混色のフレームごとには再計算しません。外部の画像生成APIや通信は使いません。

起動ロゴとオープニング用の描画は別に保持します。`drawBubbleOrigins` の10個の出発位置・大きさを待機SVGと混色Canvasで共有し、5つの色の泡と小さな中立色の泡をつなぎます。写真の編集値、保存形式、DBスキーマは変更しません。

選ばれた色のバブルは、夜空を透かしすぎて色がくすまないよう中心の色を濃くしています。背景・ナビなどの装飾の泡は軽い透過のまま、反射の向きと膜の描画を共有します。38色の定義と抽選方式は維持しています。

開発用「サンプル追加」は抽選後のHomeで、写真欄の下に常時表示します。既存の写真や記録を消す操作ではありません。オープニングは中央のロゴだけを表示します。

## 夜空への統一（2026-10-27）

外観テーマの選択を削除し、Home・カレンダー・設定・各ダイアログ・完成画面・オープニングを夜空に統一しました。以前保存した `light` / `dark` / `system` の値はDB互換性のため保持しますが、表示には使用しません。端末の外観設定も画面の配色に影響しません。

`accentTokens` が今日の色から背景下部の光・泡の反射・操作欄の色を計算します。Homeだけにあった固定背景の上書きを削除し、全画面で同じ夜空の描画を共有します。抽選前は中立色、抽選後と再訪時は今日の色がにじみます。オープニングは従来の承認済みバブルロゴだけを中央表示し、スキップ・読み込み待機・短縮設定を維持します。写真・記録・38色の定義・画像書き出しの処理は変更しません。

### iOS上部領域の色（2026-10-27）

HTML・body・theme-color・Manifestの起動色を `#0a1126` に固定しました。HTML内の同期スクリプトはCSS・React・IndexedDBより前に実行され、過去の外観設定や初期描画用キャッシュを読みません。背景色をアニメーションさせず、ホーム画面起動のiOSでは上端に同色の非操作レイヤーを置きます。セーフエリアが0pxの状態でも上端に色を確保し、復帰時にも再同期します。今日の色は下部の夜空へ反映し、上部の基準色は変えません。

iOSが管理するネイティブのステータスバー領域はWebから直接描画できないため、iPhone実機での最終確認が必要です。保存データの初期化やアプリの削除・再追加は不要です。

## セットアップ

Node.js 20以降とpnpmを用意してください。

```bash
pnpm install
pnpm dev
```

表示されたローカルURLをブラウザで開きます。本番ビルドは `pnpm build`、ビルド結果の確認は `pnpm preview` です。コード整形は `pnpm format` です。

## 主な操作

1. 初回の4ページの説明を進めるかスキップします。
2. Homeのグレーのバブルを押して、その日の色を引きます。色は端末の日付で固定されます。
3. 色が決まると写真欄を表示します。通常モードでは4・6・9枚を選び、写真を撮影またはライブラリから追加します。ライブラリは複数枚を選べます。
4. 写真を長押しして並べ替え、タップして拡大、位置、回転、差し替え、削除を操作します。位置はプレビューをドラッグするか、左右・上下のスライダーで調整できます。元画像の枠外部分まで移動できます。
5. 指定枚数が揃ったら「完成」を押し、コラージュのプレビューで確認後にロックします。完成の演出中にも作品を表示します。
6. 完成画面またはCalendarから完成日の画像を保存、共有します。共有機能が使えない環境では画像をダウンロードします。

枚数を減らす際に現在の写真が収まらない場合、残す写真を選ぶ画面が開きます。ランダムチャレンジは注意書きの確認ボタンを押してONにします。ONにすると、色を引くときに枚数も決まり、その日は固定されます。Homeは確定した枚数だけを表示します。色を引いた後にONにした場合はその日の枚数を維持し、同様に翌日までロックします。チャレンジONで色を引いた日はスイッチに「ロック中」と表示し、翌日のローカル日付0:00に解除します。再読み込みしてもロックは維持されます。

写真の間隔はHomeとカレンダー詳細の小さな写真イラストで選びます。左が4枚の写真を隣り合わせた「すき間なし」、右が間隔を空けた「すき間あり」です。画面には文字ラベルを出さず、読み上げ名とツールチップに意味を持たせています。選択は日ごとに保存され、カレンダーの表示と書き出し画像にも反映します。完成後も間隔を変更できます。写真の順序・編集値・枚数・完成時刻は引き続きロックされます。以前の記録は「すき間あり」で表示します。

抽選後はバブルと色名だけを横並びに表示します。色のヒント機能は削除しました。

ホームの空き枠は点線で区切り、「すき間あり」では写真の間を離します。スマートフォンでも差が分かるよう、編集画面と完成画像の間隔は共通の基準幅28px（完成画像の幅1200px）を使います。「今日のパレット」は44pxです。`domain/collageLayout.ts` の写真の縦横比を保持し、完成画像の外周・フッターは各デザインで調整します。完成確認の `CompletionPreview` と完成後・カレンダーの `ExportedCollage` は、共通の `useCollageExport` と `CollageImageView` から保存用のJPEGをそのまま表示します。縁・ロゴ・トリミング・仕切りを別のCSSで再現せず、画像の準備完了後に確定ボタンを有効にします。

完成確認で100文字までの「ひとこと」を任意入力できます。`completeToday(memo)` が完成時刻と一緒に同じ作品データへ保存します。カレンダーで完成作品を開くと、完成画像と、登録されている場合のひとことだけを表示します。ひとことがなければ入力ボタンや空欄は表示しません。右上の「…」からデザイン・間隔・ひとことの変更、点数、保存・共有を開け、矢印で鑑賞表示へ戻れます。開き直すと鑑賞表示になります。完成直後の画面でもひとことを編集でき、空欄で保存すると削除できます。メモは `DayRecord.memo` としてIndexedDBに保存し、写真や点数、完成後のロック、書き出し画像には影響しません。既存記録に項目がなくてもそのまま読み込めます。`ArtworkMemoField` が共通の入力欄、`ArtworkMemo` が完成後の編集、`domain/memo.ts` が文字数と正規化、`AppContext.setMemo` が完成後の保存を担当します。

Homeの写真欄の下にある「サンプル追加」は、ペールグリーン系の9枚から空き枠を埋めるテスト用機能です。抽選後に表示し、登録済み写真やその日の色は上書きしません。素材はアプリ内に同梱し、外部サービスから取得しません。生成方法と機能の削除手順は `src/dev/README.md` を参照してください。

設定の「テストデータを初期化」で、確認後に保存済みの色・写真・完成記録をすべて削除できます。その他の設定は残ります。この操作は元に戻せません。

## Liquid Bubble UI

深いネイビー〜紫の夜空を基調に、今日の色を背景・シャボン玉の膜・選択状態へ反映します。未抽選時は中立色です。写真自体にはフィルターを適用しません。

`LiquidBackdrop` が背景の装飾を描き、`CollageStage` が画面の残り高さからグリッドの幅を計算します。写真枠の元の縦横比と4・6・9枚の固定レイアウトを保ち、ホームの完成ボタンまで画面内に収めます。極端に高さの低い画面では通常のスクロールを許可します。

`ui/theme.ts` は相対輝度から文字色を選び、夜空の背景で読めるアクセント色を調整します。保存された色と画像書き出し用の色には変更を加えません。外観は夜空に固定しています。

### 色決定のモーション

背景で浮遊する10個のバブルが中央へ集まり、渦状に回りながら中心へ収束します。各塊を先頭と慣性を持った尾の連なりで表現し、塊が重なる部分の密度場を合成して輪郭と色をつなぎます。剛体を回転させるのではなく、尾が遅れて曲がり、合流する流れをCanvasで描画します。陰影・光沢・3D表現は使用せず、最後にその日の1色へまとまり、全体のアクセントを更新します。背景バブルは演出中も非表示で待機モーションを保ち、終了時は少しずつ時間をずらしてフェードインします。中央の装飾線もフェードインし、描画の切り替わりで突然現れることを避けています。

`ui/useColorRitual.ts` は表示上の段階だけを管理します。抽選は既存の `AppContext.drawToday` に委譲し、開始時に一度だけ保存します。再読み込み、画面の非表示、日付変更でも再抽選しません。非表示時は演出を終了し、結果へ進みます。タイマーは終了・アンマウント時に解除します。

枚数セレクター、完成ボタンには、くぼみと広がりを持つSVGシルエットをCSSマスクとして適用します。ラベルは独立して描くため、形状によって文字やクリック領域が欠けません。

`ui/bubbleGeometry.ts` は待機中の液体状の輪郭をSVGで生成します。`ui/fluidMix.ts` は演出中だけ使用する密度場・尾のばね追従・色の混合を担当します。計算バッファを再利用し、各ノードの周辺だけを走査します。requestAnimationFrameは演出終了・非表示・アンマウント時に停止します。

`components/LiquidColorScene.tsx` は実際のバブル位置を測って描画するため、画面サイズに応じて中央へ集まります。時間・回転数・尾のばねと減衰・描画解像度・途中の混色は `constants/liquidMotion.ts` で調整できます。4・6・9枚の選択背景も液体の塊として移動します。`prefers-reduced-motion` では浮遊・輪郭変形・渦の混合を省略して直ちに結果を表示し、選択・ナビの移動も即時にします。

## 状態と保存

- `DayRecord` はローカル日付、色、枚数、写真の間隔、抽選時のチャレンジモード、写真の並びと編集値、完成時刻、一言メモ、完成画像のデザインを持ちます。
- 追加時に表示用画像（最大1800px、JPEG品質0.78）とカレンダー用サムネイル（最大360px、JPEG品質0.72）を作ります。拡大トリミング用の解像度を維持し、追加する写真の保存容量を抑えます。2026-10-27以前の品質0.88／0.78と比較し、同梱写真6枚のChromium計測では約30%削減しました。効果は写真とブラウザーにより変わります。既存写真は再圧縮しません。IndexedDBでは別テーブルに保存し、起動時はサムネイルだけを読みます。写真本体はHome表示、日付詳細、書き出し時に読み込みます。
- `AppContext` が状態と操作をまとめ、画面コンポーネントはDexieを直接呼びません。
- `domain/crop.ts` の共通計算を、画面の写真表示と画像書き出しの両方で使用します。画像の余剰部分だけを移動範囲とし、枠の背景が見えないようにします。
- `StoragePort` を別実装に差し替えれば、保存場所を変えられます。
- 設定にはランダム枚数、書き出しロゴ、チュートリアル完了を保存します。旧外観設定の値は互換性のため保持します。
- 完成画像は5種類の仕上げから選べます。バブルの窓は半透明の水のような縁と透過PNG、ほかはJPEGです。アプリ画面の夜空背景は画像に含めません。完成確認・完成直後・カレンダー詳細では、保存・共有される画像そのものを表示します。ロゴ表示設定と既存の保存データを引き継ぎます。

ブラウザのサイトデータを削除すると写真も消えます。プライベートブラウズでは保存が持続しない場合があります。

## ロゴとオープニング

オープニングのカプセル型ロゴは `public/branding/picpa-logo-source.png` に同梱しています。元の文字と虹色の縁をそのまま描画し、位置を固定します。完成画像では添付された白ロゴを `picpa-white-logo-source.png` として保持し、`picpa-white-logo.svg` の描画マスクで暗い背景だけを透明にします。文字形は描き直しません。SVGの再生成は `python3 scripts/export-white-logo.py` で行えます。

完成画像のロゴは、色の標本・今日のパレットではフッター右下、バブルの窓では下側の縁、黒枠・白枠では下部中央に小さく配置します。白枠では同じ形を黒色で描きます。ロゴOFFでは画像に含めず、バブルの窓・黒枠・白枠の下部余白も縮めます。写真の位置は変えません。ロゴや縁は色マッチ度の採点に含めません。ホームの空き枠は四角で、「すき間なし」の境目は点線です。

`components/OpeningScreen.tsx` は共通の夜空を背景にロゴだけを中央表示し、約2.6秒後に0.6秒でホームへフェードします。周囲のバブルや星は表示しません。ロゴをタップするとスキップできます。端末の「視差効果を減らす」設定では待ち時間を短縮します。画面遷移や写真ピッカーから戻る際は再表示せず、アプリのページを新しく読み込んだときだけ表示します。初回チュートリアルはオープニングの終了後に表示します。

ロゴは起動前に読み込み、IndexedDBの準備を待ってホームへ進みます。読み込み失敗や画像の通信待ちが長い場合でも、オープニングだけで操作が止まらないようにしています。見本画像は `assets/branding/picpa-opening-preview.jpg` と `assets/branding/picpa-finished-artwork-ui.jpg` に保存しています。

## iPhoneアプリ化に向けて

UI、日付・色・画像処理、保存を別ディレクトリに分けています。Capacitor化では `StoragePort` をネイティブの保存方式に差し替え、Homeの写真入力とCalendarの共有処理をカメラ・写真・共有プラグインに置き換えられます。日付切り替えは端末ローカル時刻で判定します。

画像は追加時に圧縮し、写真本体を必要なときだけ読み込んでいます。長期間の大量保存を想定する場合は、バックアップとストレージ使用量の管理を追加できます。

カレンダーは月の週数（4〜6週）に応じて残りの画面高を分配し、短い画面では日付の円も縮めて1画面に収めます。

## 色マッチ度・混色レシピ

完成後、Home・完成演出・カレンダー詳細に0〜100点の色マッチ度を表示します。Canvasで各写真のトリミング・回転・拡大を適用し、96px幅に縮小してOklabで比較します。

採点v3は「主役の色」を重視します。`domain/colorSubject.ts` で、周辺・写真全体との色／明るさの差と弱い中央優先度から視覚的な目立ち度を推定します。ぼかしてノイズを弱め、目立つ色のグループを先に選び、その後で今日の色と比較します。今日の色に近い部分だけを探して主役にする方式ではありません。色相が近い明暗のバリエーションはまとめ、白いハイライトや無彩色の影は色の証拠として弱く扱います。小さな色の点（色グループが写真の1.5%未満）は除外します。

主な色の一致度78%・目立つ領域全体の一致度22%を合わせ、色のまとまりでも調整します。面積そのものの加点はありません。撮影による明暗や彩度の差を許容しつつ、離れた色相と彩度の違いを従来より強く減点します。グレーは色相ではなく明るさ・彩度で比較します。写真ごとの点数は等しく平均し、枠・余白・ロゴは採点しません。

主役推定は軽量な視覚的ヒューリスティックで、物体を認識するAIではありません。色の似た背景、複数の被写体、強い照明の色などでは人の判断と異なる場合があります。採点定数は `constants/colorMatch.ts` に分離しています。サンプル写真だけへの特別な加点やファイル判別はありません。

目立ち度の色コントラストは [Achanta et al., Frequency-tuned salient region detection (CVPR 2009)](https://www.epfl.ch/labs/ivrl/research/saliency/frequency-tuned-salient-region-detection/) の考え方を参考にしています。本実装はOklab・周辺差・色グループを組み合わせた独自の採点で、論文の検出精度を再現・保証するものではありません。

結果・各写真のスコア・採点バージョン・写真編集値の署名は `DayRecord.colorMatch` に保存します。古い記録の追加フィールドは任意で、DB構造の変更は不要です。過去の完成作品は閲覧時に計算し、採点バージョンや写真編集値が変わった場合のみ再計算します。間隔変更ではスコアは変わりません。欠損写真を0点として扱わず、計算失敗時は再計算を表示します。初期化中に古い計算結果が記録を復活させないよう世代番号で保護します。

`constants/mixRecipes.ts` に38色のイラスト用混色レシピを定義しています。オレンジは赤と黄色、ラベンダーは赤・青・白、ベージュは黄土・茶・白などを使います。動きと1日1回の抽選は維持し、塊の色だけをレシピに置き換えます。顔料らしい見え方として中央の混色を徐々に最終パレットへ寄せ、結果の色には正確に収束させます。

`pnpm test` でレシピの網羅性、色の近さ、無彩色、白背景の主役、画面端の主役、小さな色の点、複数の色、キャッシュの無効化を確認できます。

### 点数表示と完成後の設定

### iOSホーム画面版の上部クリップへの対応

一部のiOSでは、ホーム画面に追加したWebアプリの上部をOSが不透明なステータスバー領域として確保し、`safe-area-inset-top` が0でもWebの描画領域が短くなる場合があります。[WebKitの不具合報告301994](https://bugs.webkit.org/show_bug.cgi?id=301994) に同じ症状が記録されています。この領域にはDOM・SVG・Canvasで描けないため、前節の背景拡張だけでは対応できません。

`ui/useViewportGuard.ts` はiOSのstandalone状態・実際の上端インセット・画面とviewportの高さの差を読み取り、該当する表示状態を判別します。`ui/viewport.ts` の共通座標関数で、上端にかかるバブルだけを浮遊・輪郭変形分の余白を含めて下げ、水平に切れた半円にならないようにします。SVGと混色Canvasで同じ開始位置を使い、混色の軌道・タイミング・保存データは維持します。通常のSafari・全画面を描画できるiOS・拡大中の表示ではこの補正を適用しません。OSが管理するステータスバー内まで装飾を描けることは保証しません。

### 混色中の透明な膜と描画の切り替え

混色Canvasの塊に、透明な中心部（現在の不透明度0.38）と見やすい薄い縁（最大0.84）を設けています。塊同士が重なる部分も1つの密度場で描くため、不透明度を重ねて濃くする構成ではありません。ばね・勾玉状の軌道・回転・混色レシピ・全体の時間は維持しています。

`constants/liquidMotion.ts` の `FLUID_SURFACE` で透明度と切り替えを調整できます。`ui/fluidSurface.ts` の共通時間関数で、開始時のSVG→Canvasと終了時のCanvas→SVGの描画比率を補完関係にしています。終了時のSVGの表示率はCanvasの描画フレームと同じ時計からMotionValueへ渡し、別々のフェードによる濃さの跳ね上がりを抑えました。色を引く前の背景バブルも、同じ開始時間・イージングで切り替えます。

### 今日の色に合わせた背景と丸いバブル

`ui/theme.ts` は紺〜紫の夜空を基調に、選ばれた色から光と膜の色を計算します。赤・緑・青などで周囲の泡の雰囲気が変わり、色を引く前は灰色のままです。保存される今日の色自体は変更しません。`ui/bubbleGeometry.ts` では待機中の輪郭の揺れを小さくして円形に近づけました。混色Canvasでは絵の具の彩度と透明膜の濃さを調整し、既存の軌道と時間を保ちながら色を見やすくしています。

### 深いネイビーと今日の色の配色（2026-10-15）

`ui/theme.ts` で深いネイビーを基調に、今日の色がにじむ背景・明るい選択色・色付きの反射と陰影を計算します。中間色は彩度と深みを少し強め、ペールグリーン・ラベンダー・クリームなど明るい色は元の淡さを維持します。白・黒・無彩色には彩度を加えません。色を引く前は灰色です。

バブルの配色は `bubbleTones` にまとめ、半透明の本体と深い影、明るい反射を組み合わせています。混色の最後も同じ表示用の色へ収束します。選択部分・有効な主ボタンは今日の色を明確に反映し、濃いネイビーの文字とのコントラストを確保します。38色・Light/Dark両方で文字のコントラストと淡い色の明るさをテストします。

## 選べる完成画像（2026-10-16）

完成確認・完成直後・カレンダーの「…」メニューで、実際の完成画像を見ながら次の5種類を選べます。

完成後のHomeも、選択したデザインの完成画像を表示します。`HomeArtwork` が保存・カレンダーと共通の `useCollageExport` を使うため、ロゴ・装飾・写真間隔も反映されます。表示は画面内に全体が収まるよう縮小し、バブルの窓の透明部分にはHomeの背景が見えます。カレンダーでデザインを変更してからHomeへ戻った場合も、その選択を表示します。完成前のHomeは通常の編集グリッドで、写真間のすき間に外枠の背景を見せることで、白い仕切りを外枠と統一しています。

- **黒枠**（初期選択）・**白枠**: 写真と単色の枠・すき間だけのシンプルなレイアウトです。黒、白の順に並びます。ロゴ設定以外のバブル・色名・日付の装飾はありません。
- **色の標本**: ネイビーの写真グリッドに、今日の色の帯・フッターのバブル・色名・日付を添えます。写真同士の間にバブルは重ねません。
- **バブルの窓**: 同じ大きさの角丸四角の写真を、今日の色が透ける水のような一続きの縁でつなぎます。4枚は2×2、6枚は2×3、9枚は3×3の正方形グリッドです。外周も滑らかな角丸四角で、縁は今日の色を保つ半透明の膜と、境界に沿った薄い反射で描きます。立体面の陰影や交差部の稜線は加えません。枠の外は透明なPNGで保存します。
- **今日のパレット**: 今日の色を背景に、各写真から抽出した3色の色見本と、写真由来の小さなバブルを添えます。

`DayRecord.artworkStyle` は任意フィールドで、作品ごとの選択をIndexedDBに保存します。既存の作品もそのまま開け、未設定・未知の値は黒枠を表示します。明示的に保存された選択は維持します。完成確認では、コラージュの種類を完成後もカレンダーから変更できることを案内します。完成後もデザインと写真間隔は変更できます。写真の追加・削除・並べ替え・編集のロック、完成時刻、メモ、色マッチ度は維持します。バブルの窓では輪郭に合わせて写真の切り取り範囲が変わりますが、写真を引き伸ばして変形させる処理はありません。

主な実装:

- `constants/artwork.ts`: 5種類の定義、初期選択、出力幅、バブルの窓の角丸・縁幅。
- `domain/artworkLayout.ts`: 写真・フッター・ロゴの位置。`domain/artworkCanvas.ts`: コードで描くバブルの輪郭・連結した縁の陰影・色見本・文字。
- `domain/waterMaterial.ts`: 今日の色を保つ半透明の膜と、柔らかい反射の配色。透明度と縁の光沢は `constants/artwork.ts` の `WATER_MATERIAL` で調整します。
- `domain/photoCanvas.ts`: 編集値を使う共通の写真描画。採点もこの写真のみの描画を使い、完成画像の縁・色見本・背景・ロゴは採点しません。
- `domain/photoPalette.ts`: 切り取った写真の小さなサンプルから、面積の大きい異なる色を抽出します。今日の色へ寄せる処理や外部AI・通信はありません。
- `ui/useCollageExport.ts`: 写真を一度読み込み、5種類の画像を生成して切り替え時に再利用します。写真・間隔・ロゴが変わると再生成し、途中で閉じた処理と不要なURL・Bitmapを解放します。
- `components/ArtworkStyleSelector.tsx`: 保存する画像そのものを縮小した選択見本。プレビュー・ダウンロード・共有で同じBlobを使います。

出力は幅1200pxです。バブルの窓は写真・半透明の縁だけを残す透過PNGで、外側に背景や色名・日付の帯を描きません。ほかの4種類はJPEGです。透過プレビューの市松模様は画像に書き込みません。アプリの夜空や操作ボタンは含みません。承認済みのPicPaロゴはデザインの下部に配置し、設定からON/OFFできます。白枠では同じロゴの形を黒で表示します。間隔は各デザインの縁を残した範囲で反映します。Capacitor化でも、画像描画とUI・ローカル保存を分離した構成を使えます。
