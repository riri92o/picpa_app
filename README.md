# PicPa

1日1色を引き、その色に合わせて4・6・9枚の写真でコラージュを作る、モバイル向けのローカルWebアプリです。写真、完成記録、設定はIndexedDBに保存します。サーバーやアカウントは使いません。

## セットアップ

Node.js 20以降とpnpmを用意してください。

```bash
pnpm install
pnpm dev
```

表示されたローカルURLをブラウザで開きます。本番ビルドは `pnpm build`、ビルド結果の確認は `pnpm preview` です。コード整形は `pnpm format` です。

## 主な操作

1. 初回の4ページの説明を進めるかスキップします。
2. Homeのグレーのバブルを押して、その日の色を引きます。色は端末の日付で固定されます。
3. 4・6・9枚を選び（通常モードでは色を引く前も選択できます）、写真を撮影またはライブラリから追加します。ライブラリは複数枚を選べます。
4. 写真を長押しして並べ替え、タップして拡大、位置、回転、差し替え、削除を操作します。位置はプレビューをドラッグするか、左右・上下のスライダーで調整できます。元画像の枠外部分まで移動できます。
5. 指定枚数が揃ったら「完成」を押し、コラージュのプレビューで確認後にロックします。完成の演出中にも作品を表示します。
6. Calendarから完成日の画像を保存、共有します。共有機能が使えない環境では画像をダウンロードします。

枚数を減らす際に現在の写真が収まらない場合、残す写真を選ぶ画面が開きます。ランダムチャレンジは注意書きの確認ボタンを押してONにします。ONにすると、色を引くときに枚数も決まり、その日は固定されます。Homeは確定した枚数だけを表示します。色を引いた後にONにした場合はその日の枚数を維持し、同様に翌日までロックします。チャレンジONで色を引いた日はスイッチに「ロック中」と表示し、翌日のローカル日付0:00に解除します。再読み込みしてもロックは維持されます。

写真の間隔はHomeの「くっつける／離す」で選びます。「くっつける」は隙間と写真の角丸をなくします。選択は日ごとに保存され、カレンダーの表示と書き出し画像にも反映します。完成後もHomeとカレンダーの詳細画面から間隔だけを変更できます。写真の順序・編集値・枚数・完成時刻は引き続きロックされます。以前の記録は「離す」で表示します。

Homeの「サンプル」は、ペールグリーン系の9枚から空き枠を埋めるテスト用機能です。登録済み写真は上書きしません。未抽選の場合は今日の色をペールグリーンに設定します。抽選済みの場合はその日の色を保持します。素材はアプリ内に同梱し、外部サービスから取得しません。生成方法と機能の削除手順は `src/dev/README.md` を参照してください。

設定の「テストデータを初期化」で、確認後に保存済みの色・写真・完成記録をすべて削除できます。外観などの設定は残ります。この操作は元に戻せません。

```text
  components/                ナビ、コラージュ、写真の表示、モーダル、チュートリアル

  state/AppContext.tsx       画面共有状態と操作

```

## Liquid Bubble UI

オフホワイトを基調に、今日の色を液体状のSVG装飾、色バブル、選択状態へ反映します。未抽選時はグレーです。光沢、グラデーション、強い影を使わないフラットな表現にしています。

`LiquidBackdrop` が背景の装飾を描き、`CollageStage` が画面の残り高さからグリッドの幅を計算します。写真枠の元の縦横比と4・6・9枚の固定レイアウトを保ち、ホームの完成ボタンまで画面内に収めます。極端に高さの低い画面では通常のスクロールを許可します。

`ui/theme.ts` は相対輝度から文字色を選び、明るい・暗い背景用のアクセント色を調整します。保存された色と画像書き出し用の色には変更を加えません。ライト・ダーク・システムの各テーマに対応しています。

### 色決定のモーション

背景で浮遊する10個のバブルが中央へ集まり、渦状に回りながら中心へ収束します。各塊を先頭と慣性を持った尾の連なりで表現し、塊が重なる部分の密度場を合成して輪郭と色をつなぎます。剛体を回転させるのではなく、尾が遅れて曲がり、合流する流れをCanvasで描画します。陰影・光沢・3D表現は使用せず、最後にその日の1色へまとまり、全体のアクセントを更新します。背景バブルは演出中も非表示で待機モーションを保ち、終了時は少しずつ時間をずらしてフェードインします。中央の装飾線もフェードインし、描画の切り替わりで突然現れることを避けています。

`ui/useColorRitual.ts` は表示上の段階だけを管理します。抽選は既存の `AppContext.drawToday` に委譲し、開始時に一度だけ保存します。再読み込み、画面の非表示、日付変更でも再抽選しません。非表示時は演出を終了し、結果へ進みます。タイマーは終了・アンマウント時に解除します。

枚数セレクター、完成ボタンには、くぼみと広がりを持つSVGシルエットをCSSマスクとして適用します。ラベルは独立して描くため、形状によって文字やクリック領域が欠けません。

`ui/bubbleGeometry.ts` は待機中の液体状の輪郭をSVGで生成します。`ui/fluidMix.ts` は演出中だけ使用する密度場・尾のばね追従・色の混合を担当します。計算バッファを再利用し、各ノードの周辺だけを走査します。requestAnimationFrameは演出終了・非表示・アンマウント時に停止します。

`components/LiquidColorScene.tsx` は実際のバブル位置を測って描画するため、画面サイズに応じて中央へ集まります。時間・回転数・尾のばねと減衰・描画解像度・途中の混色は `constants/liquidMotion.ts` で調整できます。4・6・9枚の選択背景も液体の塊として移動します。`prefers-reduced-motion` では浮遊・輪郭変形・渦の混合を省略して直ちに結果を表示し、選択・ナビの移動も即時にします。

## 状態と保存

- `DayRecord` はローカル日付、色、枚数、写真の間隔、抽選時のチャレンジモード、写真の並びと編集値、完成時刻を持ちます。
- 追加時に表示用画像（最大1800px）とカレンダー用サムネイル（最大360px）を作ります。IndexedDBでは別テーブルに保存し、起動時はサムネイルだけを読みます。写真本体はHome表示、日付詳細、書き出し時に読み込みます。
- `AppContext` が状態と操作をまとめ、画面コンポーネントはDexieを直接呼びません。
- `domain/crop.ts` の共通計算を、画面の写真表示と画像書き出しの両方で使用します。画像の余剰部分だけを移動範囲とし、枠の背景が見えないようにします。
- `StoragePort` を別実装に差し替えれば、保存場所を変えられます。
- 設定には外観、ランダム枚数、書き出しロゴ、チュートリアル完了を保存します。

ブラウザのサイトデータを削除すると写真も消えます。プライベートブラウズでは保存が持続しない場合があります。

## iPhoneアプリ化に向けて

UI、日付・色・画像処理、保存を別ディレクトリに分けています。Capacitor化では `StoragePort` をネイティブの保存方式に差し替え、Homeの写真入力とCalendarの共有処理をカメラ・写真・共有プラグインに置き換えられます。日付切り替えは端末ローカル時刻で判定します。

画像は追加時に圧縮し、写真本体を必要なときだけ読み込んでいます。長期間の大量保存を想定する場合は、バックアップとストレージ使用量の管理を追加できます。

カレンダーは月の週数（4〜6週）に応じて残りの画面高を分配し、短い画面では日付の円も縮めて1画面に収めます。

## 色マッチ度・混色レシピ

完成後、Home・完成演出・カレンダー詳細に0〜100点の色マッチ度を表示します。Canvasで各写真のトリミング・回転・拡大を適用し、96px幅に縮小してOklabで比較します。

採点v2は「主役の色」を重視します。`domain/colorSubject.ts` で、周辺・写真全体との色／明るさの差と弱い中央優先度から視覚的な目立ち度を推定します。ぼかしてノイズを弱め、目立つ色のグループを先に選び、その後で今日の色と比較します。今日の色に近い部分だけを探して主役にする方式ではありません。色相が近い明暗のバリエーションはまとめ、白いハイライトや無彩色の影は色の証拠として弱く扱います。小さな色の点（色グループが写真の1.5%未満）は除外します。

主な色の一致度65%・目立つ領域全体の一致度35%を合わせ、色のまとまりでも調整します。面積そのものの加点はありません。撮影による明暗や彩度の差を許容し、反対の色相には追加の減点があります。グレーは色相ではなく明るさ・彩度で比較します。写真ごとの点数は等しく平均し、枠・余白・ロゴは採点しません。

主役推定は軽量な視覚的ヒューリスティックで、物体を認識するAIではありません。色の似た背景、複数の被写体、強い照明の色などでは人の判断と異なる場合があります。採点定数は `constants/colorMatch.ts` に分離しています。サンプル写真だけへの特別な加点やファイル判別はありません。

目立ち度の色コントラストは [Achanta et al., Frequency-tuned salient region detection (CVPR 2009)](https://www.epfl.ch/labs/ivrl/research/saliency/frequency-tuned-salient-region-detection/) の考え方を参考にしています。本実装はOklab・周辺差・色グループを組み合わせた独自の採点で、論文の検出精度を再現・保証するものではありません。

結果・各写真のスコア・採点バージョン・写真編集値の署名は `DayRecord.colorMatch` に保存します。古い記録の追加フィールドは任意で、DB構造の変更は不要です。過去の完成作品は閲覧時に計算し、採点バージョンや写真編集値が変わった場合のみ再計算します。間隔変更ではスコアは変わりません。欠損写真を0点として扱わず、計算失敗時は再計算を表示します。初期化中に古い計算結果が記録を復活させないよう世代番号で保護します。

`constants/mixRecipes.ts` に38色のイラスト用混色レシピを定義しています。オレンジは赤と黄色、ラベンダーは赤・青・白、ベージュは黄土・茶・白などを使います。動きと1日1回の抽選は維持し、塊の色だけをレシピに置き換えます。顔料らしい見え方として中央の混色を徐々に最終パレットへ寄せ、結果の色には正確に収束させます。

`pnpm test` でレシピの網羅性、色の近さ、無彩色、白背景の主役、画面端の主役、小さな色の点、複数の色、キャッシュの無効化を確認できます。

### 点数表示と完成後の設定

点数はカウントアップせず計算結果をそのまま表示します。一言コメントはカレンダーの作品詳細だけに表示します。完成した日は通常モードでもランダムチャレンジの切り替えをロックし、ON/OFFの状態を維持します。端末の翌日0:00に解除します。

暖色のレンガ・テラコッタ・赤茶・アンバー・ハニー・クリームと、ホワイト・ブラックを追加しました。既存の色IDと保存作品は維持しています。白・黒のバブルには視認性のため薄い輪郭を付けています。

ビルドのアセット参照は相対パス（Viteの `base: "./"`）です。サブディレクトリでの配信やCapacitor内での読み込みに対応しやすくしています。IndexedDBはホスト・ポート単位なので、同じホストとポートの別パスでは保存データを共有できます。

## アプリアイコン

虹色のバブルに山と湖の風景を映した角丸アイコンを登録しました。`index.html` にfavicon・apple-touch-icon・Web App Manifestを指定しています。ホーム画面追加時の名前はPicPa、表示はstandaloneです。相対URLなので同じビルドをサブディレクトリでも読み込めます。

`public/icons/` に16・32・48・180・192・512・1024pxのPNG（Web用は角の透過を維持、180/1024pxは不透明）、`public/favicon.ico` に16/32/48pxのICOを保存しています。将来のCapacitorアプリ化では1024px版をアイコン生成の入力に使えます。編集元・生成プロンプトは `assets/branding/` に、サイズを書き出すスクリプトは `scripts/export-icons.py` にあります。再生成にはPillowが必要ですが、アプリ実行にPythonは不要です。

Web用の登録方式: [MDN manifest icons](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/icons)、[Apple Web Clip icons](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html)。端末へのホーム画面追加はSafariなどのブラウザーから行ってください。
